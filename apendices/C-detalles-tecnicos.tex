\section{Datos utilizados}

El único conjunto de datos que el sistema carga es el catálogo cerrado
de materias, niveles y temas, sembrado por migración
(\path{V20__m2_temas_seed.sql}) y ampliado luego a partir del
catálogo vivo (ADR-M2-04). No se usa ningún conjunto de datos personales
para entrenar o ajustar modelos. El relevamiento de precios de Superprof
que respalda el capítulo~\ref{cap:economica} se conserva en
\path{apendices/superprof-precios.csv} y se analiza en el
apéndice~\ref{apx:precio}.

\subsection{Esquema de base de datos}

El esquema se construye con 47 migraciones de Flyway (\texttt{V1} a
\texttt{V47} al 14/10/2026). Como ninguna migración aplicada se edita,
las tablas iniciales se completan con migraciones posteriores. Los
listados siguientes son extractos textuales de las migraciones.

\begin{lstlisting}[language=SQL, caption={Usuarios (extracto de \texttt{V2\_\_m1\_identidad.sql})}, label={lst:esquema}]
CREATE TABLE identidad.usuarios (
    id                           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    dni                          VARCHAR(20) NOT NULL UNIQUE,
    nombre                       VARCHAR(150) NOT NULL,
    apellido                     VARCHAR(150) NOT NULL,
    fecha_nacimiento             DATE NOT NULL,
    tipo                         VARCHAR(20) NOT NULL
                                 CHECK (tipo IN ('ADULTO', 'MENOR', 'TUTOR')),
    capacidad_estudiante         BOOLEAN NOT NULL DEFAULT FALSE,
    capacidad_adulto_responsable BOOLEAN NOT NULL DEFAULT FALSE,
    adulto_responsable_id        UUID REFERENCES identidad.usuarios(id),
    password_hash                VARCHAR(255) NOT NULL,
    estado_cuenta                VARCHAR(20) NOT NULL DEFAULT 'ACTIVA'
                                 CHECK (estado_cuenta IN ('ACTIVA', 'SUSPENDIDA')),
    created_at                   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT chk_adulto_tiene_capacidad CHECK (
        tipo != 'ADULTO' OR (capacidad_estudiante OR capacidad_adulto_responsable)
    ),
    CONSTRAINT chk_menor_tiene_responsable CHECK (
        (tipo = 'MENOR' AND adulto_responsable_id IS NOT NULL) OR
        (tipo != 'MENOR' AND adulto_responsable_id IS NULL)
    )
);
\end{lstlisting}

\begin{lstlisting}[language=SQL, caption={Reservas (extractos de \texttt{V9\_\_m4\_reservas.sql} y \texttt{V30\_\_m4\_exclusion\_por\_rango.sql})}, label={lst:esquema-reservas}]
CREATE TABLE reservas.reservas (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    pagador_id          UUID NOT NULL REFERENCES identidad.usuarios(id),
    beneficiario_id     UUID NOT NULL REFERENCES identidad.usuarios(id),
    tutor_id            UUID NOT NULL REFERENCES identidad.usuarios(id),
    solicitud_origen_id UUID REFERENCES reservas.solicitudes_sesion(id),
    horario             TIMESTAMPTZ NOT NULL,
    precio              NUMERIC(10,2) NOT NULL CHECK (precio >= 0),
    estado              VARCHAR(20) NOT NULL DEFAULT 'pendiente_pago'
                        CHECK (estado IN ('pendiente_pago', 'confirmada', 'en_curso',
                                          'finalizada', 'cancelada', 'no_show_estudiante',
                                          'no_show_tutor', 'no_show_doble'))
    -- (se omiten motivo_cancelacion, created_at y sus restricciones)
);

-- V30: sin superposicion de rangos horarios, por tutor y por alumno
ALTER TABLE reservas.reservas ADD CONSTRAINT ex_reservas_rango_tutor
    EXCLUDE USING gist (tutor_id WITH =, tstzrange(horario, horario_fin, '[)') WITH &&)
    WHERE (estado <> 'cancelada');
ALTER TABLE reservas.reservas ADD CONSTRAINT ex_reservas_rango_beneficiario
    EXCLUDE USING gist (beneficiario_id WITH =, tstzrange(horario, horario_fin, '[)') WITH &&)
    WHERE (estado <> 'cancelada');
\end{lstlisting}

\begin{lstlisting}[language=SQL, caption={Transacciones (extracto de \texttt{V11\_\_m5\_pagos.sql}) e índice semántico (\texttt{V7\_\_m2\_matching.sql})}, label={lst:esquema-pagos}]
CREATE TABLE pagos.transacciones (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    reserva_id          UUID NOT NULL REFERENCES reservas.reservas(id),
    mp_payment_id       VARCHAR        NOT NULL,
    monto_bruto         NUMERIC(10, 2) NOT NULL CHECK (monto_bruto >= 0),
    comision_plataforma NUMERIC(10, 2) NOT NULL
                        CHECK (comision_plataforma >= 0 AND comision_plataforma <= monto_bruto),
    estado              VARCHAR(20) NOT NULL DEFAULT 'retenido_escrow'
                        CHECK (estado IN ('retenido_escrow', 'liberado',
                                          'reembolsado', 'pausado_denuncia')),
    liberar_at          TIMESTAMPTZ,
    intentos_liberacion INT NOT NULL DEFAULT 0 CHECK (intentos_liberacion >= 0),
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE matching.perfiles_tutor_matching (
    tutor_id                UUID PRIMARY KEY REFERENCES identidad.usuarios(id),
    materias_niveles_ids    UUID[] NOT NULL DEFAULT '{}',
    embedding               VECTOR(384),
    activo_para_matching    BOOLEAN NOT NULL DEFAULT FALSE
);
\end{lstlisting}

El nombre \path{retenido_escrow} es anterior al modelo de cobro A
(ADR-M5-02): con ese modelo el dinero ya está en la cuenta del tutor, y el
estado indica que todavía no cerró la ventana lógica --hasta 24 horas
después de la clase-- en la que \sistema{} puede ordenar el reembolso.

\section{Ejecución de las pruebas}

La suite del backend corre solo con JDK~21: el
\texttt{maven-enforcer-plugin} rechaza otra versión y, en ese caso, no se
ejecuta ninguna prueba. Las pruebas de integración necesitan Docker,
porque Testcontainers levanta una base \path{pgvector/pgvector:pg16}.

\begin{lstlisting}[caption={Ejecución de las suites}, label={lst:pruebas}]
# backend (desde backend/, con JAVA_HOME apuntando a un JDK 21)
./mvnw -B test        # reporte de cobertura: target/site/jacoco

# frontend (desde frontend/)
bun run lint          # oxlint
bun run test:e2e      # Playwright + axe-core

# motor de matching (desde matching-service/)
uv run pytest -q
\end{lstlisting}

Al 14/10/2026 la suite del backend registraba 661 pruebas, 0 fallas, 0
errores y 5 omitidas --las pruebas del \gls{ocr} real, que se saltean si
el equipo no tiene Tesseract instalado y que en el CI sí corren--, con
una cobertura de líneas del 85,6\,\% medida con JaCoCo (ADR-000-05).
