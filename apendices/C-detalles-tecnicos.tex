\subsection{Esquema de base de datos}

El esquema se construye con 55 migraciones de Flyway, de \texttt{V1} a
\texttt{V60} (la numeración saltea V51, V53, V55, V57 y V59); la última,
\texttt{V60\_\_m3\_estudiante\_admitido.sql}, es del 27/10/2026. Como
ninguna migración aplicada se edita, las tablas iniciales se completan con
migraciones posteriores. El resultado son nueve esquemas, uno por módulo,
con 47 tablas de dominio; las tablas de Quartz (\path{QRTZ_*}) viven en el
esquema \texttt{public} (ADR-000-01). El diagrama entidad-relación de cada
esquema y el diccionario de datos completo están en la
sección~\ref{sec:apx-modelo-datos}. Los listados siguientes son extractos
textuales de las migraciones que ilustran las restricciones más
relevantes.

\begin{lstlisting}[language=SQL, caption={Usuarios (extracto de \texttt{V2\_\_m1\_identidad.sql})}, label={lst:esquema}]
CREATE TABLE identidad.usuarios (
    id                           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    dni                          VARCHAR(20) NOT NULL UNIQUE,
    nombre                       VARCHAR(150) NOT NULL,
    apellido                     VARCHAR(150) NOT NULL,
    fecha_nacimiento             DATE NOT NULL,
    tipo                         VARCHAR(20) NOT NULL
                                 CHECK (tipo IN ('ADULTO', 'MENOR', 'TUTOR')),
    capacidad_estudiante         BOOLEAN NOT NULL DEFAULT FALSE,
    capacidad_adulto_responsable BOOLEAN NOT NULL DEFAULT FALSE,
    adulto_responsable_id        UUID REFERENCES identidad.usuarios(id),
    password_hash                VARCHAR(255) NOT NULL,
    estado_cuenta                VARCHAR(20) NOT NULL DEFAULT 'ACTIVA'
                                 CHECK (estado_cuenta IN ('ACTIVA', 'SUSPENDIDA')),
    created_at                   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT chk_adulto_tiene_capacidad CHECK (
        tipo != 'ADULTO' OR (capacidad_estudiante OR capacidad_adulto_responsable)
    ),
    CONSTRAINT chk_menor_tiene_responsable CHECK (
        (tipo = 'MENOR' AND adulto_responsable_id IS NOT NULL) OR
        (tipo != 'MENOR' AND adulto_responsable_id IS NULL)
    )
);
\end{lstlisting}

\section{Modelo de datos}\label{sec:apx-modelo-datos}

Esta sección documenta las 47 tablas de los nueve esquemas del dominio
con todos sus atributos. Cada tabla tiene sus tipos, su clave primaria,
sus claves foráneas y sus restricciones (\texttt{NOT NULL},
\texttt{UNIQUE}, \texttt{CHECK} y \texttt{EXCLUDE}). Por esquema hay un
diagrama entidad-relación; el diagrama general, con los nueve esquemas y
las claves foráneas entre ellos, es la figura~\ref{fig:der-general} del
capítulo~\ref{cap:marco-tecnologico}.

\paragraph{Cómo se obtuvo.} La estructura no se transcribió de los
archivos SQL. Se aplicaron las 55 migraciones, en orden, sobre una base
vacía de PostgreSQL~16 con pgvector, y se leyó el esquema resultante del
catálogo del motor. Así quedan incorporados los \texttt{ALTER},
\texttt{DROP CONSTRAINT} y \texttt{RENAME} de las migraciones
posteriores. El script \path{scripts/diccionario/generar.py} del
repositorio de este documento hace esa lectura y escribe esta sección y
los diagramas. Las descripciones de tablas y atributos están en
\path{scripts/diccionario/descripciones.py}, y el script se detiene si
una tabla o una columna de la base no tiene descripción. La versión que
se documenta es la de la rama principal del repositorio del sistema al
27/10/2026 (commit \texttt{0f09a3e}, última migración \texttt{V60}).

\paragraph{Qué no se incluye.} Las 11 tablas \path{QRTZ_*} del esquema
\texttt{public} son el almacén estándar de Quartz para los trabajos
programados (ADR-000-01). Las crea \path{V3__quartz_tables.sql} con el
esquema que publica Quartz y no modelan el dominio.

\paragraph{Cómo leer las tablas.} La columna \emph{Clave} marca PK
(clave primaria), FK (clave foránea) y UQ (valor único). La columna
\emph{Nulo} indica si el atributo admite nulos; un ``no'' equivale a
\texttt{NOT NULL}. Los tipos son los de PostgreSQL: \texttt{timestamptz}
es una fecha y hora con zona horaria, \texttt{varchar(n)} un texto de
hasta $n$ caracteres, \texttt{numeric(10,2)} un importe con dos
decimales, \texttt{vector(384)} un vector de pgvector y
\texttt{uuid[]} un arreglo de identificadores. Debajo de cada tabla se
listan sus restricciones con el nombre que tienen en la base y sus
índices secundarios. Las expresiones se muestran simplificadas: sin las
conversiones de tipo implícitas que agrega PostgreSQL y con
\texttt{IN (\ldots)} en lugar de \texttt{= ANY (ARRAY[\ldots])}.
\emph{Migraciones} son las que crean o modifican la tabla.

\paragraph{Cómo leer los diagramas.} Las relaciones usan la notación
pata de gallo. En el extremo de la tabla que tiene la clave foránea, la
pata de gallo con un círculo significa ``cero o muchos'' y la barra con
un círculo, ``cero o uno''. Este último caso se da cuando la clave
foránea es además única, como en una relación 1 a 1. En el extremo de
la tabla referenciada, dos barras significan ``exactamente uno'' y
corresponden a una clave foránea obligatoria. Una barra con un círculo
significa ``cero o uno'' y corresponde a una clave foránea que admite
nulos. El rótulo de cada línea es la columna, o las columnas, de la
clave foránea. Las tablas de otro esquema se dibujan con borde punteado.
Para que cada diagrama entre legible en una página, las entidades
muestran sus atributos de clave y la cantidad de atributos restantes,
que se detallan en el diccionario.

\section{Ejecución de las pruebas}

La suite del backend corre solo con JDK~21: el
\texttt{maven-enforcer-plugin} rechaza otra versión y, en ese caso, no se
ejecuta ninguna prueba. Las pruebas de integración necesitan Docker,
porque Testcontainers levanta una base \path{pgvector/pgvector:pg16}.

\begin{lstlisting}[caption={Ejecución de las suites}, label={lst:pruebas}]
# backend (desde backend/, con JAVA_HOME apuntando a un JDK 21)
./mvnw -B test        # reporte de cobertura: target/site/jacoco

# frontend (desde frontend/)
bun run lint          # oxlint
bun run test:e2e      # Playwright + axe-core

# motor de matching (desde matching-service/)
uv run pytest -q
\end{lstlisting}

Al 18/10/2026, en la integración continua, la suite del backend
registraba 859 pruebas, 0 fallas y 1 omitida, con una cobertura de
líneas del 89,6\,\% medida con JaCoCo (ADR-000-05); la de Playwright,
252 pruebas exitosas, y la de pytest, 44 de 44. En un equipo sin
Tesseract instalado se saltean además las pruebas del \gls{ocr} real, que
en el CI sí corren.
